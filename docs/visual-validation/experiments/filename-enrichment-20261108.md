# Historical filename-dependency enrichment

## Evidence boundary

The live inspection API can add current source-formula evidence to an older
saved-state diagnosis. Its `source_supplement` remains a separate object. The
original saved values, counts, examples and evidence identity are preserved.
Source cached values are labelled independently in the shared live/static
presentation. Finding a path never establishes exclusive causation or changes
a visual verdict.

Two retained Enron cases were checked through the actual local HTTP API.

the supplement. This is checked structurally, including all retained examples.

## Isolated execution

The automatic approval review rejected an additional host using the production
Control Room root because two hosts could share writable controls/caches. No
such host was started. The accepted experiment instead copied only the two
source bundles, exact portable reports and minimal record metadata into a new
study under `G:\deltasieve-work\filename-enrichment-isolated-20261108`.
Its host used port 18891 and group target zero. No scientific runner or Excel
process was started by the test.

The first isolated startup was rejected by the existing control invariant
because target zero was combined with paused dispatch. Its stderr is retained.
The second startup used target zero with dispatch unpaused. The source reports
and bundle copies remained byte-identical to production. The API returned both
supplemented diagnoses successfully. Repeating the first request returned an
identical cached result. The own host was stopped with PID, creation time and
executable verification and confirmed absent afterward.

Responses were 1,786 bytes each. Observed local request times were 42.14 and
19.99 milliseconds in this single concurrent-load trial. These are diagnostic
latencies, without a corpus-throughput implication. The retained private
`acceptance.json`, response files, `api-metrics.json`, ownership and startup logs
record the test. The production Enron runner continued and was subsequently
observed at 7,300 completed comparisons with four active groups.

## Verification and limits

Focused Rust tests check immutable primary evidence, missing source explanations,
malformed retained diagnoses and bounded selectors. Shared JavaScript tests
check source labels, exact filename-call highlighting, primary counts and that
source values never receive OR/SDR captured-value labels. The fixture-specific
diagnostic reader also recognizes the first retained source directly.

This acceptance checks the API and presentation logic. A fresh browser layout
check remains a subsequent step. Existing static
exports are not rewritten or automatically enriched. The limited diagnostic
parser retains its existing reference, text and search budgets independently
of scientific capture coverage.
