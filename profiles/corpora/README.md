# Corpus workbook manifests

These versioned manifests describe the supplied original corpus archives.
Workbook bytes are not stored in Git. Each workbook records its exact archive
member name, original member index, expanded member size, CRC32 and SHA-256.
The archive object records the SHA-256 of the ZIP bytes and its byte size.

The catalog was generated by streaming every selected member from the existing
local archives. ZIP member names and indices remain unchanged. Destatis contains
1,182 workbooks and Data.gov contains 9,117. Enron remains on its existing
configuration pending the separately announced corpus replacement.

The existing download cache filenames are source lookup keys. Their hexadecimal
names must not be interpreted as the SHA-256 of the downloaded ZIP bytes. Use
`archive.sha256` for archive integrity and the individual workbook hashes for
extracted artifacts.

## Rebuilding a manifest

Use `tools/catalog-corpus.py` with an existing archive, a declared archive
SHA-256, corpus ID, display name, source URL and a new output path. The generator
rejects a mismatched source checksum, unsafe member paths, duplicate workbook
names and an archive changed during cataloging. It does not extract workbooks.

## Integration and download status

The ordinary configurator and artifact acquisition path still need to consume
these manifests. Their presence does not establish that local artifact reuse,
partition selection or first-run downloading has been integrated or accepted.

The URLs were copied from the existing study request without private access
tokens. Anonymous HEAD requests to both file URLs returned HTTP 404 on
2026-11-08. Public download availability therefore remains a release gate.
Existing local ZIP files can be checked against the recorded archive hashes.
